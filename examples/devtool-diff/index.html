Command walkthrough

The brief arrives before the diff.

Three commands turn a pull request into a reading order. Each one leaves a line you can paste into a terminal.

  1. 01

    Index the change by intent.

    Kestrel groups files by what they alter, so a guard and its test land in the same entry.

    ~/work/relayINDEX
    $ kestrel index --pr 482
  2 groups · 1 risk · 0.4s

  2. 02

    Put the exposed edges first.

    Public APIs, migrations and missing tests move above formatting noise in the brief.

    ~/work/relayRANK
    $ kestrel brief --rank risk
  guard.ts:43 → cli/flags.ts:18

  3. 03

    Ask which test carries the claim.

    Each group points to a test file, or reports the gap plainly. A missing test is never dressed up as coverage.

    ~/work/relayPROOF
    $ kestrel proof --group 01
  parser_guard.test.ts · 14/14 PASS

Does Kestrel send my code anywhere?

No. The parser and the index run locally. Network access is only used for update checks, and can be disabled.

Which languages are supported?

TypeScript, JavaScript, Python, Go and Rust today. A language without a parser still gets a file-and-test brief.
